# M10-TOOLCHAIN-V433-RESTORE

**Status:** DONE_STRONG

The repository is back on the toolchain it documents, Lean `v4.33.0`, and the whole
library compiles there with no errors and no warnings.

## What had drifted

`lean-toolchain` read `leanprover/lean4:v4.28.0` while `README.md`, the release notes and
the evidence notes all described Lean `v4.33.0`. Several modules had been rewritten
against the older Mathlib and `cslib` APIs that go with `v4.28.0`, so the sources no
longer matched the documented toolchain either.

## The pin

* `lean-toolchain`: `leanprover/lean4:v4.33.0`;
* Mathlib: local checkout at `.lake/packages/mathlib`, commit
  `6f1ef4e5dd` (the latest revision on that toolchain — the first one, `db584cd6`, leaves
  a few modules failing);
* `cslib`: local checkout at `.lake/packages/cslib`, commit
  `3951377e5a3f5772737f11cd62bc5bb6a72f95d1`, the revision that moves `cslib` to Lean
  `v4.33.0` (its own manifest pins Mathlib `db584cd6`, the `v4.33.0` tag);
* `lake-manifest.json` regenerated by `lake update`, so that it agrees with the `path`
  requirements of `lakefile.toml` (it previously recorded Mathlib as a `git` dependency
  and omitted `cslib` altogether, which made `lake build` refuse to start).

## Sources brought forward to the current APIs

* `Start/TM2Forward.lean`, `Start/TM2Capstone.lean` — `Turing.Reaches`, `Turing.eval` and
  `Turing.mem_eval` are now `StateTransition.Reaches`, `StateTransition.eval` and
  `StateTransition.mem_eval`.
* `Start/TM2Partrec.lean`, `Start/TM2PolyTime.lean` — `Computability.FinEncoding` is
  deprecated in favour of a bare encoding function together with a `Fintype` alphabet, so
  `partrec_of_tm2Computable`, `partrec_of_tm2ComputableInPolyTime` and
  `haltsWithin_of_tm2ComputableInPolyTime` are stated for `ea : α → List αΓ`,
  `eb : β → List βΓ`.
* `Start/CwaType.lean`, `Start/CwaTypeModel.lean`, `Start/CwaTypeModelSigma.lean` —
  morphisms of `Type u` are now the bundled `TypeCat.Hom`, so pointwise equality of
  morphisms goes through `ConcreteCategory.hom_ext`; this is packaged once as
  `CwaTypeModel.types_hom_ext`, the converse of the existing
  `CwaTypeModel.types_hom_congr_fun`.
* `Start/Representation.lean` — `cslib`'s full β-reduction is now the congruence closure
  `Xi Beta` of the root rule, so the constructors are `Xi.base (Beta.beta …)`, `Xi.appL`,
  `Xi.appR`, `Xi.abs`; `Term.LcAt` is `Bool`-valued; `Term.subst_intro` no longer takes a
  local-closure argument; and confluence is `Term.confluent_fullBeta`.
* Deprecation and linter follow-ups across the library: `Mathlib.Data.Nat.Lattice` →
  `Mathlib.Order.Lattice.Nat`, `Set.mem_setOf_eq` → `Set.mem_ofPred_eq`, `Set.mem_setOf` →
  `Set.mem_ofPred`, `push_neg` → `push Not`, removal of four `change` tactics that do
  nothing and of one unused `simp` argument. `Cwa.Model` carries a scoped
  `set_option linter.checkUnivs false in`, exactly as Mathlib does for
  `CategoryTheory.Cat`: its three universes are independent but occur only inside a `max`.
